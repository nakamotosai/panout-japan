# 四章の正文拡張のための要点リスト — 地震 / 犯罪 / 内閣 / 住宅

## この文書について(用途)

`japan.ouuut.com` の四章 —— **地震(/quake/)・犯罪(/crime/)・内閣(/cabinet/)・住宅(/housing/)** —— は、地図とグラフは動くが、読み物としての本文を持っていない。次に正文を書き起こすとき、何をどの順に書くかを先に決めておくための要点リストが本書である。

- 本書は**正文ではない**。各項目は書き起こしの材料であり、そのまま掲載する文章ではない。
- **本文を書くのは次回の作業**。本章の `COPY` への見出し追加、`src/build.py` の `build_*()` への `<section>` 追加、`site/` の再生成は本書の対象外。
- 本書に載せる数字・フィールド名・パスは、すべて本リポジトリのファイルから実際に読んで確認した値である。確認できなかったものは `[要確認]` と書く。
- 対象は地震・犯罪・内閣・住宅の四章。天気・人口の二章は既に本文の型を持っているので、書き起こしの参照元としてだけ扱う。

## 四章のいまの状態

- 四章の静的 HTML は、`src/build.py` の `build_quake()` / `build_crime()` / `build_cabinet()` / `build_housing()` が `<main id="main" class="chapter-app-page">` の中に置くのが `h1.sr-only`、`p.sr-only`、`div.stage`(`stage-poster` / `stage-caption` / `stage-live`)の三つだけ。**散文の本文はなく、`h2` も一本もない**(ja 版も `/zh-Hans/` 版も 0 本。対照として `/population/` は 4 本ある)。
- 四章のページは **ja / zh-Hans / zh-Hant / en の四本の静的ページ**として既に生成されている(`LANGS` / `PREFIX`)。`site/` の出力に四言語が揃い、`site/sitemap.xml` にも四言語分の URL が入っている。**本文を足すときは ja だけを書けば済む仕事ではない**。
- 見出しや本文を `COPY` に足せば四言語に展開する(`COPY` は ja / zh-Hans / en の 3 列。繁体は `COPY_HANT = hant.convert(簡体列)` で自動生成)。
- 数値は「ページに出る値」「`site/data/*.csv`」「JSON-LD(`dataset_node()`)」の三か所に散る。書き起こしの前に一致を確かめる。

# 第1章 地震(/quake/)

## 【データの口径】

1. 一次出典は USGS ANSS Comprehensive Catalog(ComCat)。`app/quake/data/quakes.json` は **40,145 件**、`time` は **2000-01-01T19:30:57Z 〜 2026-08-09T15:48:10Z**(UTC)、`mag` は **4.0 〜 9.1**。
2. 抽出条件は `tools/rebuild_quake_catalog.py` に明文化されている。東経 **120–150 度**、北緯 **20–50 度**、`mag >= 4.0`、`time >= 2000-01-01`。残すフィールドは `id / lon / lat / depthKm / mag / time / place` の 7 つ。タイル(`app/quake/data/quakes/tiles/r_*.json`)から `quakes.json` を作り直す。
3. タイルの manifest は `app/quake/data/quakes/manifest.json`。`coverageStart: "1970-01-01"`、`coverageEnd: "2026-08-10"`、`minMag: 4`、`tileDeg: 20`、タイル 9 枚、`yearMin: 1970` / `yearMax: 2026` / `recentYear: 2000`。→ **年次モードは 1970 年まで遡れるが、本文の主系列は 2000 年以降**。この差は本文で明示する。
4. 見出し・キャプション・`llms.txt` の件数は `Q_N = len(Q)` から自動生成。本文でも 40,145 は「データから生成される値」として扱い、別の数字を直書きしない。
5. エネルギーは `log10E = 1.5M + 4.8`(ジュール、`COPY["m.cal.q"]`)。年の合計は単純和。
6. 2011 年は件数 **5,852 件 = 14.6%**。エネルギー比は `quakes.json` から同じ式で計算すると **86.2%**(`PCT_2011_E` を使う `COPY["card.quake.claim"]` も 86.2 になる)。ただし `COPY["q.beat1.p"]` は **86.7% を直書き**しており一致しない → `[要確認]`(本文で使う値と生成元を統一する)。
7. 統計枠は 4 つ(`COPY["q.stat.count"]` 震源数 / `q.stat.strong` M6以上 / `q.stat.max` 最大 / `q.stat.energy` 2011年のエネルギー)。自分で数えた値は **M6 以上 422 件**、最大 **M9.1**。
8. 深さは七段の階調(`COPY["q.beat2.p"]`「七段の深さ階調。赤い点ほど浅く、海溝の形が浮かぶ」)。**色 = 深さ**であり、多さでも深刻さでもない。
9. マップの三モード(`app/quake/view.js`)。「直近30日」(`eq-mode-live`、USGS の直近30日公開カタログ)、「著名」(`eq-mode-famous`、読み物としての解説で**予報ではない**)、「年次」(`eq-mode-review`、1970 年から一年ずつ積み上げる)。
10. 著名地震モードの外部リンクは `ja.wikipedia.org`、ja 以外は `en.wikipedia.org`(`app/quake/view.js`)。**一次データではなく百科事典の解説**である旨を出典表記に書く。
11. 既知の偏差は `COPY["m.err.5"]`「カタログの検知能力は時代で変わる。2000 年代初頭は小さい地震の取りこぼしがある」。
12. 静的ポスター(`quake_poster()`)は 2011-03-11 M9.1 を一点だけ強調し、枠は東経 120.5–151.5 度 / 北緯 22.0–47.5 度。**代表の 1 点であって平均ではない**。
13. CSV は `site/data/quakes.csv`(`time,lon,lat,depth_km,mag,place`、40,145 行 + ヘッダ)。
14. JSON-LD の `temporalCoverage` / `spatialCoverage` は `dataset_node()` に渡す値で、地震章は `Q_END` と「120–150 度」から生成する(この二つは実データと一致)。残る食い違い `[要確認]`: `COPY["d.year.note"]` は「2026年は7月15日まで」のままで、実データの最終日(2026-08-09)と一致しない。本文で使う値と生成元を統一する。

## 【読み方】

1. 点ではなく年で見る。`q.index.title`「27年を、一年ずつ」/ `q.index.sub`「各年の震源数・最大マグニチュード・月別分布・主な地震」。年次の語彙は `d.year.months`(月別の震源数)/ `d.year.top`(主な地震)/ `d.year.energy`(エネルギー)/ `d.year.share`(年間シェア)。
2. 回数とエネルギーは別。太平洋側の帯状の密集と、2011 年の単発の巨大化。`q.beat1.t`「回数より、エネルギー」。**震源の多さを危険度として読ませない**。
3. 深さは色。`q.beat2.t`「深さは、色」。日本海溝・伊豆諸島沖の浅い縁と、その下に沈み込む深い面。
4. 画面の数字と本文の数字を一致させる。上の 4 統計枠を本文の数値アンカーにする。
5. ポスターは 1 点。見出しの直下に「ポスターは代表の 1 点」と一文置く。
6. 起動後は別の世界。`q.beat3.t`「起動すると、地球儀」/ `q.beat3.p`(WebGL の地球を読み込み、回す・拡大する・年を切る)。静止画だけでは伝わらない操作を文章で補う。
7. 再現手順を書く。`tools/rebuild_quake_catalog.py` がタイルから `quakes.json` を再生成する。「どのタイルから、どのフィルタで、どのフィールドを残すか」を【方法と出典】で述べる。

## 【よくある質問】

1. **Q 気象庁の地震情報と何が違うのか。**
   答えの骨子: 気象庁は国内で検知した地震の実況と情報発表、本章は USGS ComCat を日本周辺の矩形から切り出したもの。**検知網・規模評価・発表の時点が別系統**で、震源数の一致は期待できない。
2. **Q M4 未満の地震はなぜ見えないのか。**
   答えの骨子: 抽出条件が `mag >= 4.0`。図は「記録された M4 以上の分布」であり「地震の全体分布」ではない。
3. **Q 2011 年が突出しているのは件数が多いからか。**
   答えの骨子: 件数は全体の 14.6%、エネルギーは 86.2%(または 86.7% `[要確認]`)。**件数とエネルギーは別の話**で、章の主題は後者。
4. **Q 図の色は何を表すのか。**
   答えの骨子: 震源の深さを七段で表す(赤い点ほど浅い)。**多さでも深刻さでもない**。
5. **Q「著名」モードは地震速報か。**
   答えの骨子: 違う。既知の地震を読み物として再演するモードであり、**予報ではない**。
6. **Q 1970 年からあるのに本文が 2000 年からなのはなぜか。**
   答えの骨子: 年次モードは manifest の `coverageStart: 1970-01-01` まで遡るが、本文の統計は `quakes.json`(2000 年以降、M4 以上)に揃えている。

# 第2章 犯罪(/crime/)

## 【データの口径】

1. 一次出典は警視庁「区市町村の町丁別、罪種別及び手口別認知件数」令和7年(2025)年計および令和8年月次累計。人口は東京都「住民基本台帳」令和8年1月1日。出典 URL とライセンスは `app/crime/data/meta.json` の `sources`(5 件、CC BY ほか)。
2. 空間単位は東京都内の町丁 `counts.chome = 5234`(`app/crime/data/points.json` は 5,234 件)と区市町村 `counts.munis = 62`(`app/crime/data/muni.json` は 62 件)。
3. `points.json` のフィールドは `n`(町丁名)/ `w`(区市町村名)/ `lng` / `lat` / `t`(刑法犯総数)/ `bi`(侵入窃盗)/ `nb`(非侵入窃盗)/ `r`(粗暴犯)/ `v`(凶悪犯)/ `o`(その他)/ `pop`(常住人口)/ `g`(分档記号)/ `r8` 〜 `r8o`(令和8年累計の同系統)。
4. `muni.json` のフィールドは `ward` / `area` / `pop` / `R7{total,violent,rough,breakin,nonbreakin,other}` / `R8cum{...}` / `nodata`。**「R7」は令和7年の年計、「R8cum」は令和8年の累計で期間が違う。直接比較できない。**
5. 率 = 認知件数 ÷ 人口 × 1,000(`COPY["m.cal.c"]`)。**人口 200 人未満の町丁は率を出さず**、地図では灰色、表では件数のみ併記(`c.beat2.p`、`d.ward.note`。実装は `app/crime/view.js` の `chomeRateOf()` が `pop < 200` で null を返す)。
6. 分档 `g` は A〜E(各 1,022〜1,023 件)+ 人口欠損の `*` 122 件。**相対参考であり公式の評価ではない**(`meta.json` の `method`)。
7. 既知の偏差は `meta.json` の `notes` 5 件。月次は累計値(前月差分 = 当月累計 − 上月累計、推定)/ 認知件数 ≠ 発案数で届出率の影響を受ける / 人口欠損町丁(以下不詳・中央防波堤等)は `*` 表示で分档対象外(**`counts.pop_missing = 122`**) / 声かけ・前兆事案は町丁別の集計がなく図に含まない(デジポリスへ外部リンク) / **交通事故を含まない**。
8. 欠損の例は `meta.json` の `pop_missing_examples`(「あきる野市小峰台」「千代田区丸の内2丁目」「中央区以下不詳」など)。
9. 地図の枠。静的ポスターは東京本土の矩形(東経 138.9–139.96 度、北緯 35.46–35.92 度)だけを写し、島嶼部は枠外。この矩形で数えると **5,159 町丁**(`c.caption` の計算式)。都内は 5,234 町丁なので、**本土 5,159 / 都内 5,234 の差**を本文で明示する。
10. 境界は `app/crime/data/muni_poly.json` と `chome_poly.json`(出典: dataofjapan/land「地球地図日本」、出典明記・営利目的は権利者へ報告)。底図は国土地理院「淡色地図」。**地図の線とラベルは外部データ由来**である旨を出典欄に書く。
11. 免責は `app/crime/view.js` の FAQ(`faqTitle: "口径と免責"`、ja 4 問)に「本図は公式統計の分布を示すのみで、いかなる地域の安全性の評価・保証も行いません。単独の判断材料としないでください」。本文の冒頭と末尾の二か所に置く。
12. `[要確認]` K=2000 の小標本収縮。`app/crime/view.js` の `metaL2` と FAQ、`meta.json` の `method` は「小人口収縮(K=2000)」を行うと書くが、`COPY["m.err.6"]` は「犯罪の `g` 列は表示に使っていない。K=2000 の縮小(経験ベイズ)は行っていない」と書く。実装(`buildScales()` / `colorForRate()` / `chomeRateOf()`)は率を `log1p` の分位で段に切っており、`g` は塗り分けに使っていない。**どちらを正とするかを先に決める。**
13. `[要確認]` `app/crime/view.js` の `metaL1` は「常住人口 1,400万人基準」と書く。`points.json` の `pop` の合計は **14,010,460**(約 1,401 万人)なので、1,400 万は表示上の概数として扱う。
14. CSV は `site/data/crime.csv`(`ward,chome,pop,total,violent,rough,breakin,nonbreakin,other,rate_per_1000`)。**令和7年の値のみ**で、令和8年累計の列は無い。`pop` が 0 の行は `rate_per_1000` が空になる。

## 【読み方】

1. 件数と率を分ける。`c.beat1.t`「率で見る」/ `c.beat1.p`「件数は人口に比例する。人口1,000人あたりに直すと、町丁の性格が見える」。
2. 小さい分母を信じない。`c.beat2.t`「小さい分母」。人口 200 人未満は率が定義されない。**灰色 =「率なし」であり「安全 / 危険」ではない。**
3. 分档は都内の相対値。A〜E は都内の分位で切った相対ランクで、他都道府県とも他年度とも比べられない。
4. 昼間人口の歪みを念頭に置く。駅前・繁華街は分母が常住人口なので率が押し上げられる。**居住の安全性を示す数字ではない。**
5. 罪種別に分ける。`app/crime/view.js` の `metrics` は 6 指標。総数には窃盗も粗暴犯も混ざるので、「総数 → 窃盗 → 粗暴犯」の順に分解して見せる。
6. 令和7年の年計と令和8年の累計を分ける。`d.ward.r8`「2026年累計」。**令和8年は途中経過で、年率ではない**(`meta.json` の notes「月次は累計値」)。
7. 地図に無いものを説明する。本土 5,159 / 都内 5,234、島嶼部は枠外、人口欠損 122 町丁。「**地図に無いことは、ゼロではない**」を一段落で。

## 【よくある質問】

1. **Q 認知件数と発案件数は同じか。**
   答えの骨子: 違う。認知件数は届出を経た件数であり、届出率の影響を受ける。実際の被害規模とは一致しない。
2. **Q 人口 200 人未満の町丁はなぜ率が灰色なのか。**
   答えの骨子: 小さい分母では 1 件で率が大きく跳ね、順位が安定しない。率を出さず、件数のみ併記する。
3. **Q 繁華街の率が高いのはなぜか。**
   答えの骨子: 分母が常住人口である一方、昼間の流動人口がはるかに大きい。**口径による偏り**であり、居住の安全性の評価ではない。
4. **Q 2025 年と 2026 年の数字は比べられるか。**
   答えの骨子: 2025 は年計、2026 は月次累計で期間が違う。直接比較ではなく「年初来の推移」として読む。
5. **Q この地図は「安全な町丁」を示すのか。**
   答えの骨子: 示さない。都内相対の分档であり、**安全性の評価・保証ではない**。単独の判断材料にしない。
6. **Q 島しょ部の町丁はどこにあるのか。**
   答えの骨子: データには含まれる(都内 5,234 町丁)が、**地図の枠は本土のみ**で島嶼部は枠外。件数と率は表で見られても、地図には出ない。

- `## 5,234 の町丁をどう読むか`(【読み方】1〜3)
- `## データと口径`(出典・単位・率・分档)
- `## この数字が語らないこと`(既知の偏差・欠損 122・島嶼部枠外・K=2000 の不一致・免責)
- `## よくある質問`
- `## 方法と出典`

# 第3章 内閣(/cabinet/)

## 【データの口径】

1. 出典は NHK 放送文化研究所の月例政治意識調査(2000–2017)、NHK 選挙 WEB(2018–2026)、および日経・朝日・時事・読売・JNN・共同の各社世論調査(`COPY["m.b.p"]`、`app/cabinet/data.json` の `_meta.description`)。
2. `_meta` の値は `version: "8.4-nikkei-oct-kyodo-sep"`、`real_source_count: 646`、`derived_count: 0`(**導出値ではなく実測値のみ**)。`polls` は 646 件、`cabinets` は 14 件、月は **331**。
3. `polls` の内訳(自分で数えた): NHK 321、日経 298、朝日 14、時事 6、読売 3、JNN 2、共同 2。
4. 月次平均は月内の全調査の算術平均。**実測月だけを結び、補間しない**(`COPY["m.cal.b"]`、`d.pm.note`)。**「点の数 646」と「月の数 331」は違う。**
5. 系列の先頭は `1998-08-01` の日経世論調査(小渕恵三、25.1)、最終は `2026-10-17` の朝日新聞世論調査(高市早苗、50.0)。

## 【読み方】

1. 地図の色と町の数字は別物。ポスターは区の中央値、町名カードは町の平均。どの基準で塗っているかを最初の段落で書く `[要確認]`。
2. 平均と中央値の差を見る。区のカードには `unit` と `unit_mean`、`total_med` と `total_mean` が並ぶ。右に裾を引く分布なので、都心ほど平均が高く出る。この差そのものを一つの話題にする。
3. 単価と総額を分ける。単価(円/m2・万円/m2)は面積を吸収して町同士を比べられる。総額(万円)は「その町で成約した物件がいくらだったか」で、戸数と面積の構成に依存する。`app/housing/view.js` の `metrics` は `unit`(平均m2単価)と `total`(平均成約価格)を切り替える。
4. 件数を同時に読む。`n`(成約件数)を必ず添える。成約 1 件の町と成約 300 件の町を同じ重みで読ませない。
5. 4 四半期を一つの窓として読む。単四半期はノイズが大きい。`docs/housing-feasibility.md` に検討の記録がある(本文で数値を引くなら原典を確認する `[要確認]`)。
6. 「高い = 投資価値が高い」ではない。単価は成約した物件の平均であり、売り出し中の物件全体の評価でも、将来の値上がり率でもない。
7. 鮮度。公表は約 1 四半期遅れ。`generated: "2026-10-22"` は生成日、対象は 2026Q1 まで。**新しい四半期がまだ公表されていない**ことを先頭に置く。
